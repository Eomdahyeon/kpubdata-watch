## [Unreleased]

### Changed

- Completeness null handling in `docs/detectors/quality.md` now follows kpubdata's field types (#60): numeric fields (`integer`/`number`) treat `""` and `-` as no value exactly as kpubdata's `_DEFAULT_NULL_MARKERS` does (kpubdata#615); string fields treat only JSON `null` and an empty string as no value and count `-` as a value, unless a field-level registry declaration backed by measurement says otherwise. `N/A` is dropped from the rule for lack of measured evidence, and fields kpubdata declares in `LicenseSpec.pii_columns` are never chosen for completeness, since its evidence keeps original representations and ADR 0006 (D-017) stores no personal data.
- The `PR title` check reads the title live from the API and applies kpubdata's pull-request rules — English, no issue reference or URL, at most 100 characters (kpubdata#741, #742); GitHub's `Revert "…"` title is exempt. A required check that failed no longer stays blocking once a later run of it passes: `required-check-refresh.yml` re-runs the stale failed runs of `R3 review` and `Titles` on the same head (kpubdata#759). AGENTS.md and the PR template say commit titles (= PR titles) are English and commit bodies (= PR bodies) are free, since the squash body is now the PR body (kpubdata#743).

### Added

- **Watch adopts KPubData Studio Brand v2 as its fixed visual identity** (#68); layout stays experimental (#33). `docs/VISUAL_IDENTITY.md` covers the lockup (the same K symbol, `KPubData`, a neutral `Watch` suffix), light as canonical and dark as the alternative, brand colours (Brand Blue, Data Cyan, Fresh Mint) never used for status, Healthy/Degraded/Critical/Unknown mapped to Studio's `--status-success`/`-warning`/`-failure`/`-unknown` with an icon and a word, informational changes in neutral rather than blue, and Studio's typography, density and accessibility rules (contrast, 390px, reduced motion). `docs/UI.md` drops colour rules from the experimental list and separates fixed identity from experimental layout. The one token source, `src/kpubdata_watch/web/static/brand-v2.css`, is Studio's `src/globals.css` light, dark and OS-dark blocks copied verbatim at a pinned commit, for Public Status and every UI Lab prototype to link (no UI code exists yet). `scripts/check_brand_tokens.py`, run by its unit tests in CI, fails when the token table and the file disagree, the core palette moves off Brand v2, a brand token equals a status token, a Health state maps to anything but a defined `--status-*` token, a pinned Studio link names another commit, or a UI Lab or `web/` file redefines a token; given Studio's `globals.css` (`--studio` or `STUDIO_GLOBALS_CSS`) it also fails on any value drift. The docs site drops Brand v1 Indigo for a white header with Brand Blue links (`docs/stylesheets/brand.css`).
- The MVP PRD, split by purpose: `docs/PRD.md` (the product), `docs/ROADMAP.md` (scope, order, definition of done, epics, open questions), `docs/DOMAIN_MODEL.md`, `docs/detectors/`, `docs/architecture/`, `docs/REGISTRY.md`, `docs/UI.md`, `docs/TESTING.md`, `API_CONTRACT.md` and `SECURITY.md` in English, and six ADRs in `docs/decisions/` covering decisions D-001 to D-020. `docs/index.md` maps every PRD section to the document that now holds it. Epics and open questions are GitHub issues.
- The repository, set up the same way as the KPubData series: squash-only merges with the pull request title as the commit title, the aggregate `CI gate` as the one required check, the series' label set, secret scanning with push protection, Conventional-Commit titles checked on pull requests and turned into `type:*` labels on issues, and the release workflow with the series' release-window gate.
- The package skeleton from the PRD's repository structure (`src/kpubdata_watch/`), with a `kpubdata-watch --version` command and smoke tests. Nothing is implemented yet.
- `scripts/check_independence.py` fails CI when Watch imports or declares KPubData Builder or KPubData Studio (PRD D-016); its tests plant each kind of violation and expect a failure.
- Every issue template now asks for a **Required Verification** level (V0–V5, kpubdata POLICY 18), and `scripts/check_governance.py` fails CI when a template stops asking or when `titles.yml` stops calling the series' shared conventional-title action with a failing step — the title and verification rules adopted in #3 keep their gates, and CONTRIBUTING.md documents the rule.
- `docs/detectors/freshness.md` records the live-measured freshness-field evidence (#26): three field kinds a freshness check must extract (record-modified, observation-time, composed event date), the datasets observed for each, the dataset-level `baseD` baseline, and the measurement limits (KST-naive values throughout, weather APIs unreachable from the probing host, partial key coverage).
- **ADR 0007** (#27): providers do not announce quotas through the API (measured — no quota headers or envelope fields on data.go.kr; kpubdata's `LicenseSpec.quota` is free text), so the registry declares rate limits (scope, window, count, minimum interval, source URL, verified date) in `registry/providers.yaml` and terms reusing kpubdata's `LicenseSpec` vocabulary; registry validation rejects a dataset set whose daily probe budget exceeds the declared limit, and a runtime `RateLimitError` overrides the declaration without ever counting as a provider outage. `docs/REGISTRY.md` carries the schema and the budget rule.
- `docs/detectors/quality.md` separates the two volume counts (#28): `total_record_count` (the envelope's `totalCount`, kpubdata's `RecordBatch.total_count`, query-bound, the primary anomaly signal) and `record_count` (records actually received, probe-config-bound), each with its own rolling baseline; a `record_count` persistently below the requested page size is a truncation symptom, not a volume anomaly, and the registry gains a `volume.metric` field defaulting to `total_record_count`. The names are the `ProbeResult`/`Observation` fields of `docs/architecture/README.md`, so there is one vocabulary across the architecture, quality and registry documents (#57). An unknown total (`None`) never enters the volume baseline and yields `UNKNOWN`; `0` is recorded only when the provider reports `0` (kpubdata#642), and the volume detector (Epic 8) must test both cases. `docs/REGISTRY.md`'s example now carries `volume.metric`.
- `docs/detectors/quality.md` gains completeness-field selection criteria (#29), grounded in a 30-record sample per dataset: fields are chosen by measured fill ratio before registration (identification, location, representative and time fields that are mostly filled), always-empty fields are excluded (they carry no anomaly signal — `TELNO` 30/30 empty, `addr2` 87%), one to three fields per dataset, empty representations (`null`, `""`, `-`, `N/A`) normalise to one "no value" with the original kept as evidence, and a field vanishing from the schema belongs to the contract check, not completeness.
- **ADR 0008** (#30): a breaking contract change keeps its PRD default of CRITICAL, now with explicit guards — the incident opens only after the confirmation probe agrees, the diff is computed against the last confirmed snapshot (failed/empty/truncated responses are availability or quality signals, never mass field removal), and a dataset override may lower the severity to WARNING at most, by a person only. Grounded in kpubdata 0.8.0's datago adapter carrying two pagination dialects and separate envelopes — contract drift is real on this provider family.
- **ADR 0009** (#31): confirmation counts keep the global default (2 failures open, 2 successes resolve) while the registry may adjust only `failures`, within 1–3 and with a reason — resolve stays fixed so flapping protection cannot be tuned away. Availability confirms with an immediate retry (independent of the probe interval); freshness and quality only observe on the scheduled probe, so datasets probed at ≥24h intervals should set `failures: 1` instead of waiting two days; contract breaking confirms once (ADR 0008). A watch-side probe failure (D-009) is never counted toward `failures` — it is recorded `UNKNOWN`, consistent with ADR 0002.
- **ADR 0010** (#32): the public history view and API default to 30 days — exactly the public-history retention floor, so the default never promises more than is guaranteed — and the dataset history API accepts `days` up to 90 (the internal-metadata floor), serving over-cap requests at the cap with `requested_days`/`effective_days` in the response. Change and incident listings carry no period limit; raising the default requires raising the retention floor first.
- **ADR 0011** (#35): an official notice becomes its own entity (url, title, published time, provider, an excerpt captured at registration, who registered it) linked many-to-many to incidents and changes from the operator CLI — replacing the incident's single `official_notice_url` field, because one maintenance notice spans datasets and correction notices join incidents that already carry one. Linking is informational and never resolves an incident; the observed-vs-published time pair stays a trust signal in the UI, and a future crawler matches candidates onto this structure. `docs/DOMAIN_MODEL.md` and `docs/architecture/README.md` §66 are updated to match: the incident's `official_notice_url` field is gone and the database model lists `notices` and its incident/change link table.
- **R3 review gate** (#46, kpubdata-builder#905): a pull request labelled `review:R3` now needs an approval from someone other than its author, with write access, before it can merge. The `R3 review` workflow calls kpubdata's `.github/actions/r3-review@main` on every pull request (passing when it is not R3) and again on label changes, pushes and review submissions or dismissals, with `pull-requests: read` only. An approval followed by a request for changes, a dismissed one, the author's own and a bot's do not count; one on an older head does, as branch protection's stale-approval dismissal is off. `R3 review` becomes a required status check; the approval count in branch protection stays at 0.
- The registry's `freshness` setting is described by extraction kind instead of a single `field` (#54): `kind` (`record_modified`, `observed_at`, `event_date_parts`, `dataset_reference_date`) with `fields`, a `strptime` `format` applied to the kpubdata-normalised value as a string, and a required `timezone`; a dataset with no extractable freshness declares `enabled: false` with a `reason` and its check is `NOT_APPLICABLE`. `docs/REGISTRY.md` gives one example per row of the freshness evidence in `docs/detectors/freshness.md` (#26) and the validation rules registry loading must enforce (unknown kind, wrong field count, unparsable format or timezone, missing reason); a value that does not match its format makes that observation `UNKNOWN`, never stale. `docs/detectors/freshness.md` and `docs/DOMAIN_MODEL.md` follow.

### Security

- **`Secret scan (gitleaks)` no longer fails on another branch's commits** (#50). Without `--log-opts`, gitleaks runs `git log --all`, which — combined with `fetch-depth: 0` pulling in every remote branch — walked unmerged PR branches too, so a synthetic test key on someone else's open branch turned this job, which `CI gate` needs, red for runs that never touched that branch. The job now scopes `--log-opts` to the run's own commits: a pull request scans `base..head`, a push to `main` scans `before..sha` (or just `sha` for a brand-new branch, where `before` is all zeros), and `schedule`/`workflow_dispatch` scan the default branch's full history only — never another branch. `.gitleaksignore` is unaffected. Ported from kpubdata-studio#685/#686.
